7. Time Travel and Rollback

About Time Travel

This page demonstrates Delta Lake's time travel capabilities. The time travel process:

  1. Allows querying data at specific versions or timestamps
  2. Enables rollback to previous versions to recover from errors
  3. Provides audit capabilities to understand data changes
  4. Supports point-in-time analysis for compliance and reporting
  5. Balances time travel with storage efficiency

Use the controls to write bad data, query previous versions, and rollback to see how Delta Lake's time travel works.

What's Happening Behind the Scenes

The time travel process involves several key components:

1. Query Data at a Specific Version
# Query data at a specific version df_at_version = spark.read.format("delta").option("versionAsOf", version_to_query).load(delta_table_path) count_at_version = df_at_version.count()
2. Write Bad Data
# Generate corrupted data corrupted_data = utils.generate_test_data(num_records=200, scenario='corrupted') corrupted_df = spark.createDataFrame(corrupted_data) # Add a marker to identify the corrupted data corrupted_df = corrupted_df.withColumn("Data_Quality", lit("corrupted")) # Write the corrupted data to the Delta table corrupted_df.write.format("delta").mode("append").save(delta_table_path)
3. Rollback to a Previous Version
# Rollback to the version before corrupted data was written version_to_restore = initial_version print(f"Rolling back to version {version_to_restore}...") # Perform the rollback spark.sql(f"RESTORE TABLE delta.`{delta_table_path}` VERSION AS OF {version_to_restore}")
